# BUG 修复报告

**日期**: 2026-04-28
**问题**: 数据库自动删除导致数据丢失及功能不可用
**严重等级**:  严重 - 数据丢失 + 功能完全不可用

---

## 问题描述

在实现"关闭时最小化到托盘"功能后,应用出现以下问题:
1. **数据丢失** - 所有任务和分组数据消失
2. **功能不可用** - 无法添加任务、无法创建分组
3. **控制台报错** - `DOMException: Internal error` (IndexedDB)

---

## 根因分析

### 主要问题: IndexedDB 自动删除重建逻辑

在 `src/renderer/db/tasks.ts` 的 `initDB()` 函数中存在危险的错误处理逻辑:

```typescript
// 错误代码 (第 60-82 行)
try {
  db = await openDB<TodoDB>(DB_NAME, DB_VERSION, {...})
} catch (error) {
  console.error('[Database] Failed to open database...', error)
  await deleteDB(DB_NAME)  // ← 直接删除整个数据库!
  db = await openDB<TodoDB>(DB_NAME, DB_VERSION, {...})
}
```

**问题链**:
1. 应用关闭后重新打开时,IndexedDB 可能因各种原因打开失败
2. 一旦打开失败,触发 catch 块
3. **直接删除整个数据库** (`deleteDB`)
4. 重建空数据库,所有用户数据丢失
5. 后续操作因数据库版本/表结构问题继续失败

### 次要问题: preload.js 构建配置缺失

`vite.config.ts` 没有配置 `preload.ts` 的构建,导致:
- `dist/main/preload.js` 文件不存在
- 应用启动时报 `Unable to load preload script`
- `contextBridge` 未正确暴露,部分功能受影响

---

## 修复过程

### 1. 问题定位阶段

**现象收集**:
- 左侧分组列表只显示"全部任务"
- 添加任务/分组时控制台报 `DOMException: Internal error`
- `preload.js` 加载失败

**关键发现**:
```
[Database] Starting to open database: todo-app-db-v3 version: 1
[Database] Failed to open database: DOMException: Internal error.
```

数据库初始化在 `openDB()` 阶段就失败了,导致后续所有数据库操作失败。

### 2. 尝试修复 IndexedDB (未成功)

尝试了以下方法:
- 升级数据库版本号 (v1 → v2 → v3)
- 在 upgrade 回调中删除旧表重建
- 修改数据库名称避开旧数据
- 修复 preload.js 构建配置

**结论**: IndexedDB 在当前 Electron 环境中存在兼容性问题,持续报 `Internal error`。

### 3. 最终解决方案: 迁移到 localStorage

决定完全替换数据层,从 IndexedDB 迁移到 localStorage:

**修改文件**:
- `src/renderer/db/tasks.ts` - 重写为 localStorage 实现
- `src/renderer/db/lists.ts` - 重写为 localStorage 实现
- `src/renderer/store/listStore.ts` - 移除 IndexedDB 导入
- `src/renderer/components/SettingsPanel.tsx` - 更新重置逻辑

**优势**:
- localStorage 在 Electron 中更稳定可靠
- 简化了数据访问逻辑
- 避免了 IndexedDB 的兼容性问题
- 数据量不大时性能足够

### 4. 其他修复

**preload.js 构建配置** (`vite.config.ts`):
```typescript
electron([
  {
    entry: 'src/main/main.ts',
    // ...
  },
  {
    entry: 'src/main/preload.ts',
    onstart(options) {
      options.reload()
    },
    vite: {
      build: {
        outDir: 'dist/main',
        rollupOptions: {
          output: {
            format: 'cjs',  // Electron preload 需要 CommonJS
          },
        },
      },
    },
  },
])
```

**preload.ts 语法** (`src/main/preload.ts`):
```typescript
// 从 ES 模块改为 CommonJS
const { contextBridge, ipcRenderer } = require('electron')
```

## 经验教训

1. **永远不要自动删除用户数据**
   - 数据库打开失败时应该向上抛出错误,让用户知道
   - 不应在用户无感知的情况下删除数据

2. **优先使用简单可靠的方案**
   - localStorage 对于这个待办应用完全够用
   - IndexedDB 增加了复杂度但没有带来明显好处

3. **Electron 环境需要特别注意**
   - preload 脚本必须使用 CommonJS 格式
   - 需要在 vite.config.ts 中显式配置 preload 构建

4. **添加足够的调试日志**
   - 这次修复过程中添加的日志帮助快速定位问题
   - 建议保留关键操作的日志
